# ❄️ 冷链智能物流调度系统 v3.0

基于 `cold_chain_vrp1.1.py` 重构升级的**双模块智能物流软件**：

| 模块 | 功能 |
|------|------|
| 🚚 **智能调度** | 冷链药品配送路线优化（VRP，容量+时间窗约束，前端 JS / OR-Tools 双引擎），可导出路线 JSON |
| 📦 **货品配载** | 大件货品三维装箱优化（3D Bin Packing）：尺寸不一/堆叠承重/多策略/多车分配/装卸顺序/**路线联动/工单打印/合规校验(重心偏载)** |

- **调度模型**: `min Z = m·c0 + c1·ΣL_ij·x_ijk + c2·Σt_ij·x_ijk`，温度 2~8℃
- **配载算法**: Guillotine 空间分割 + BLB 放置 + 多策略择优（体积/重量/高货/长件），支持旋转、堆叠承重、车厢体积/载重约束
- **装卸联动**: 调度模块导出路线 JSON → 配载模块导入，货品关联配送站点，卸货顺序按路线站点访问顺序自动生成
- **合规校验**: 重心/偏载分析（纵向/横向/垂直），生成合规报告（可打印）
- **技术栈**: 纯前端（JS 求解引擎 + Three.js 3D 可视化 + Leaflet 地图），可选 Python FastAPI 在线版

## 🚀 快速启动

### 方式〇：云端访问（推荐，无需任何安装）
打开已部署的云端链接，两个页面通过顶栏导航切换：
- `/` → 🚚 智能调度
- `/packing.html` → 📦 货品配载

**配载页顶部「🚀 一键全流程」**：点击后自动完成「路线规划(VRP) → 站点匹配货物 → 多车配载 → 生成工单/合规报告」全流程，无需手工切换模块。

纯前端运行，**不依赖后端服务**，任何设备随时可用。

### 方式一：单文件版（双击即用）
- **`冷链智能物流调度_智能调度版.html`** — 冷链药品配送调度
- **`冷链智能物流调度_配载版.html`** — 大件货品 3D 配载

浏览器内实时求解、调参、加载 Excel、导出，**零后端依赖**（地图/3D 需联网加载库）。

### 方式二：在线服务版（传统模式）
双击运行 **`启动智能调度系统.bat`**，脚本会自动：
1. 检测可用的 Python 环境
2. 通过 **Windows 计划任务**启动服务（进程独立于启动窗口，关闭窗口不影响运行）
3. 自动打开浏览器 `http://127.0.0.1:8000`

> 服务已运行时重复双击不会重复启动，只会打开浏览器。
> 停止服务：双击 **`停止服务.bat`**（或任务计划程序 → ColdChainScheduler → 结束）。

### 方式三：命令行
```bash
# 1. 创建并激活虚拟环境（首次）
python -m venv .venv
.venv\Scripts\activate

# 2. 安装依赖
pip install -r requirements.txt

# 3. 启动服务
python app.py
```

> 首次运行会自动下载 OR-Tools 求解器（约 40MB），请耐心等待。

## ✨ 功能特性

| 模块 | 说明 |
|------|------|
| 📦 数据管理 | 内置数据 / 上传 Excel 替换数据源，自动校验格式 |
| ⚙️ 调度参数 | 成本系数、容量、车速、时限、时间窗缓冲、求解策略等全参数可调 |

| 📋 司机任务单 | 自动生成可打印的司机执行单 |
| 📥 方案导出 | 一键导出 Excel 配送方案 |
| 🛡️ 异常数据识别 | 自动识别并标记距配送中心过远的疑似错误坐标（如数据中的成都/西安/上海等异常点） |

## 🛡️ 异常坐标处理

数据中部分网点坐标明显异常（如某"辽宁省肿瘤医院"坐标位于西安、某医院位于成都/上海，距沈阳配送中心 1100~2100km）。系统默认以 **200km 为阈值**自动排除这些疑似错误点，并在地图上以红叉标记、在警告中列出。可通过「异常点半径」参数调整阈值或关闭自动排除。

## ⚠️ 注意事项

- **地图模式**：默认使用「真实地图」模式（高德中文底图，国内访问快）。地图卡片右上角可切换底图（高德/OpenStreetMap/CartoDB）或切回「示意图」模式（离线可用）。OSM/Carto 在部分网络环境可能加载缓慢，高德底图最稳定。
- **坐标系**：高德底图为 GCJ-02 火星坐标，系统已内置 WGS84→GCJ02 转换，路线自动对齐地图，无需手动设置。
- 距离矩阵基于经纬度 Haversine 公式近似（非真实道路导航距离），实际调度建议接入地图路径 API。
- 求解为元启发式（GUIDED LOCAL SEARCH），结果近似最优；增大「求解时限」可获得更优方案。
- 206 个需求点全量求解较慢，可在「参与调度点数」中限制数量（按需求量优先）快速出方案。
